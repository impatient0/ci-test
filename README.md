# Monorepo CI/CD (Proof of Concept)

Этот репозиторий демонстрирует процесс **умной сборки и деплоя** для мульти-модульного Maven проекта. Пайплайн автоматически определяет, какие сервисы были затронуты изменениями (включая изменения в общих библиотеках), и деплоит только их.

## Как это работает

Весь процесс описан в `.github/workflows/monorepo-cicd.yml`.

1.  **Анализ (Plan Deployment):**
    *   Скрипт проверяет `git diff`.
    *   Maven строит дерево зависимостей (Reactor). Если изменилась общая зависимость, все зависимые сервисы пометятся для пересборки.
    *   Фильтрация: в сборку попадают только модули, в которых есть `deploy.env`.
2.  **Сборка и Деплой (Build & Deploy):**
    *   Запускается параллельная матрица (Matrix Strategy) для каждого сервиса.
    *   Docker-образ собирается и пушится в GHCR (GitHub Container Registry).
    *   По SSH происходит подключение к серверу: старый контейнер удаляется, новый запускается.

## Требования к сервису

Чтобы модуль автоматически попал в пайплайн CI/CD, он должен соответствовать трем критериям:

### 1. Наличие `pom.xml`
Стандартный Maven-модуль, прописанный в родительском `pom.xml`.

### 2. Файл конфигурации `deploy.env`
В корне папки сервиса должен лежать файл `deploy.env`. Он работает как флаг для CI (помечает сервис, который нужно деплоить) и задаёт конфигурацию порта.

Пример `service-one/deploy.env`:
```properties
HOST_PORT=8091
```

### 3. Корректный `Dockerfile`
В корне папки сервиса должен быть `Dockerfile`.
**Важно:** Сборка запускается из корня репозитория (чтобы в контекст попали в т.ч. и зависимости), поэтому Dockerfile должен уметь копировать родительские `pom.xml` для корректного разрешения зависимостей.

Шаблон с предварительным кэшированием зависимостей:

```dockerfile
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /app

# 1. Копируем скелет из pom.xml всех модулей (для кэша)
COPY pom.xml .
COPY shared-lib/pom.xml shared-lib/
COPY service-one/pom.xml service-one/
COPY service-two/pom.xml service-two/

# 2. Загружаем зависимости с кэшированием
RUN --mount=type=cache,target=/root/.m2 \
    mvn dependency:go-offline -pl service-one -am

# 3. Копируем исходники и собираем
COPY shared-lib/src shared-lib/src
COPY service-one/src service-one/src
RUN --mount=type=cache,target=/root/.m2 \
    mvn clean package -pl service-one -am -DskipTests

# ... Точка входа ...
```

> Альтернативный вариант: можно использовать более простые докерфайлы в модулях (без сборки) — тогда в пайплайне нужно будет добавить шаг сборки артефакта (JAR) перед сборкой самого образа.

## Настройка секретов GitHub

Для работы пайплайна в настройках репозитория (`Settings -> Secrets and variables -> Actions`) должны быть установлены:

*   `SERVER_HOST`: IP-адрес сервера.
*   `DEPLOY_SSH_KEY`: Приватный SSH-ключ (публичная часть должна быть в `~/.ssh/authorized_keys` на сервере).
